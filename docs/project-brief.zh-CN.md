# 迷雾大陆立项说明

日期：2026-11-16。状态：第1步立项草案，等待明确玩家角色与操作重心。

这份说明用于确定游戏的核心体验和近期制作边界。已确认的方向、开发建议和待定问题分别标注；建议内容会根据讨论修改。早期验证版的范围不等于正式发布版的范围。

## 已确认的基础

- 工作名称：《迷雾大陆：迷雾求生》，来自用户原始概念策划，正式名称可后续调整。
- 用户明确的整体方向：经营、建造、生存。
- 世界设定：迷雾包围可生存的土地，玩家通过资源与基地发展逐步扩大安全领地。迷雾也是特殊资源的来源。
- 原始设想包括探索、居民雇佣与生活需求、生产制造、灯塔扩张、战斗和周期攻城。各系统在首版中的范围尚未确定。
- 现有工程为Unity，已有采集、运输、仓储与工人指令原型及验证证据，可以继续复用。
- 项目发起者为UI设计师，尚无游戏行业经验。协作以可理解的体验决策、可试玩成果和明确验收为主。

## 建议的核心体验

玩家带领少量幸存者，在迷雾包围的土地上建立庇护所。通过安排劳动、建设设施和分配物资，维持居民生活，逐步积累向外扩张的能力。

优先验证三种体验：

1. 建设有用：新建筑实际改变居住、生产、运输或领地能力。
2. 经营有选择：有限劳动力和物资需要在当前生存与未来发展之间分配，调整后能看见结果。
3. 扩张有期待：驱散一片迷雾后，获得具体的新资源或发展机会，并看见下一个目标。

这些是设计假设，需要试玩证据支持。主角动作战斗与居民经营的比例仍待用户明确。

## 尚待确定的立项问题

| 决策 | 当前建议 | 为什么需要明确 |
| --- | --- | --- |
| 玩家角色与操作 | 倾向俯视指挥居民，居民执行采集、运输和建设 | 决定角色、指令、镜头、战斗和界面的设计；现有原型支持这一方向，但不替代用户选择 |
| 首发平台 | 倾向电脑，鼠标键盘 | 便于验证居民选择、建筑摆放和经营界面；移动端适配成本不同 |
| 游戏形态 | 先用本地单人环境验证；正式版是否联机待定 | 玩法实验可以本地进行，正式联机需求会影响控制权、同步、保存与运营成本 |
| 首版体验规模 | 先建立一个小地图内的完整发展阶段，再估算正式版内容 | 先取得制作与试玩依据，才能可靠估算规模 |
| 人员与预算 | 已知用户负责体验和设计判断，AI辅助规则整理、实现与验证 | 可投入时间、资金和其他参与者尚不明确，会影响美术来源、排期与发行范围 |

既有后端与数据库方案作为联机设计储备保留；此前的技术草案不代表正式联网形态已经确认。本地存档仍是现有原型的技术接续优先项。

## 建议的早期验证版

目的：验证玩家能否通过经营与建设维持一个小基地，并完成一次有意义的迷雾扩张。

内容预算的初始建议为一张小地图、约4至6名居民、木材和石料两种建材、食物及一种灯塔特殊资源。以上数量用于控制实验范围，可根据规则和试玩调整。

| 内容 | 本次需要达到的体验 |
| --- | --- |
| 工人劳动与仓储 | 复用已有采集运输流程，玩家能看懂人员和物资状态 |
| 建设施工 | 放置建筑后，材料经搬运投入施工，建筑完成后产生实际功能 |
| 居住 | 基础住所提供可理解的居住或人口容量作用，具体规则在第2步确定 |
| 食物生产与消耗 | 一种简单食物生产方式，居民持续消耗；缺粮有预警和调整余地 |
| 灯塔与迷雾 | 获得特殊资源并激活灯塔，开放一片具有新价值的土地；特殊资源获取方式在第2步确定 |
| 基础界面与引导 | 告诉玩家目标、短缺、工人状态与可采取的行动，支持新玩家完成基础操作 |
| 保存与继续 | 退出后可恢复，物资与施工状态保持一致，不重复产出或扣料 |

建议的体验过程：看见初始短缺 → 安排采集 → 建设生活与生产设施 → 调整食物和建材的劳动力分配 → 积累扩张资源 → 激活灯塔 → 发现新的发展目标。

首次体验可暂按约15至20分钟组织，用于暴露节奏问题，不作为已验证时长或上线承诺。

## 后续再验证的内容

完整动作战斗、周期攻城、多层装备技能、复杂士气、宠物、传送网络、多个生物群落和完整剧情，需要后续各自验证。它们仍属于原始愿景，是否进入正式首版要结合核心体验与制作能力决定。

早期经营验证版尚不能证明塔防部分有趣。若战斗或守城被确认为核心卖点，需要在扩大内容制作之前补做相应原型。

当前沿用简单几何表现。接近正式品质的美术、动画、声音和完整界面，在核心循环成立后以一小段品质样板验证制作成本。

## 如何判断可以进入下一阶段

第1步立项完成，需要明确玩家角色与操作、首发平台、单机或联机目标、早期验证范围，以及大致可投入的人员与资源。之后进入第2步，写具体规则和开局体验。

早期验证版完成时，需要同时检查两类结果：

- 功能：采集、运输、施工、食物消耗和扩张能连续运转；任务取消、缺料、受阻与读档不会造成重复结算或进度损坏。
- 体验：新玩家能理解近期目标和短缺原因，能作出至少一次影响发展的分工或建设选择，并理解扩张得到的收益。通过实际试玩观察判断，不能仅凭功能通过宣称好玩。

暂不承诺发布日期与总工期。先用完整原型和品质样板取得实际制作速度，再估算正式版工作量。
