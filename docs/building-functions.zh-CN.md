# 01.3 建筑功能分类

日期：2026-11-17。状态：讨论草案，按用户“考虑周全一点”的要求修订。用户已提出道路、围墙等基础设施应纳入考虑；其余分类、候选设施及具体规则仍为建议。

这份目录覆盖基地从落脚、生存、生产、扩张到防守可能需要的建筑和设施。完整目录暂按十个功能组检查覆盖情况，实际建造菜单随已实现内容逐步展开。列入目录不等于纳入早期版本，也不代表对应系统已经实现。

## 分类原则

以玩家建造的主要目的确定归属。每项设施有一个主要功能组，其他效果用标签说明；菜园不因有围栏就归防御，灯塔不因能照明就归普通照明。菜单可以通过搜索、标签或快捷入口帮助玩家找到跨类设施，入口始终指向同一项设施。

功能、形态与制作范围分别记录。道路是基础设施，形态是线段；农田是资源生产，形态是区域；土路和石路是道路的不同规格。固定设施、可建造设施、可修复遗迹属于获取方式；木制、石制和等级属于材料或发展阶段，都不单独充当功能分类。

## 完整功能目录

| 功能组 | 解决的问题 | 候选设施及子类 | 需要看得见的结果 |
| --- | --- | --- | --- |
| 基础设施 | 人员和物资如何通行，基地如何连接与分隔 | 道路、桥梁、台阶；围栏、院墙、院门；普通路灯；有需求后再考虑供水等管网 | 路线可达、通行改善、出入口明确；照明或管网是否有规则效果需另定 |
| 生活与公共服务 | 居民如何居住、进食、休息并维持生活 | 住所、供餐点；医务所；按需考虑取水点、供暖、卫生、消防、休闲与集会设施 | 居住和服务有人实际使用，短缺与服务不足可理解 |
| 资源生产 | 原料、食物与特殊资源从哪里来 | 采集营地、伐木场、采石场、矿场；农田、果园、渔场、牧场；特殊资源采集设施 | 劳动得到可搬运资源；消耗型资源与可再生资源分别定义 |
| 加工制造 | 如何把原料转为更有价值的物品 | 锯木坊、石材作坊、冶炼炉；厨房；工具、装备及特殊材料工坊 | 消耗实际原料与劳动，产出明确物品，能看懂缺料和积压 |
| 仓储物流 | 物资放哪里，如何交接与调配 | 仓库、物资堆场；有分仓需求后再考虑粮仓、中转站、配送站 | 库存位置、装卸能力或运输方式发生明确变化 |
| 探索扩张 | 如何发现未知地区并建立安全据点 | 灯塔、前哨站、探索营地；传送设施仅作远期候选 | 显露信息、驱散迷雾或建立新的活动支点，收益分别说明 |
| 军事防御 | 如何训练、驻扎和抵御入侵 | 兵营、驻军点；哨塔、箭塔、陷阱；木栅墙、城墙、城门 | 形成部队或真实防御能力，敌我通行与攻击关系明确 |
| 研究发展 | 如何解锁新能力与生产方法 | 研究台、研究所、档案设施 | 获得具体的新配方、建筑或能力；是否需要独立研究建筑待定 |
| 贸易交流 | 如何与外界交换物资和建立往来 | 交易站、商队驿站、贸易码头；对外接待设施 | 物资交换或外来人员往来有实际过程；货币与价格规则待定 |
| 景观装饰 | 如何表达玩家的布局与营地风格 | 花坛、铺地、雕像、旗帜、装饰灯具 | 外观变化清楚；是否影响舒适度或士气需明确标注 |

生活与公共服务可在内容增加后分为“居住”“饮食”“医疗与公共服务”等子组。当前没有必要为每种居民需求独立建立一套系统，也无需把目录中的十组全部做成菜单分页。研究、贸易、装饰属于覆盖未来可能性的预留项。

## 分类边界与容易遗漏的内容

**食物涉及生产、加工与消费三个环节。** 农田生产食物，厨房加工食物，供餐点提供领取或用餐服务。它们可以分属三个功能组，也可以在早期由一个设施兼任部分作用。现阶段可以先允许一种食物直接食用，避免为了分类完整就强行拉长生产链。

**水、燃料和公共服务是否成为需求，要单独决定。** 水井若产出需要搬运的水，主要归资源生产；供水管网归基础设施；只提供饮水服务的取水点可归生活与公共服务。普通路灯不自动具有驱雾能力，消防设施也只在火灾进入玩法时才需要。供暖、卫生和娱乐等同样按真实玩法需求取舍。

**围墙按用途归属，不能只按材料判断。** 分隔院落的围栏、院墙和配套院门归基础设施；抵御入侵的木栅墙、城墙和城门归军事防御。石制院墙仍可能只是场地设施。是否阻挡居民、敌人、动物、视线和攻击，分别写明；纯装饰矮篱笆若不承担通行或分隔功能，可归景观装饰。

**居民加入、居住与军事训练是不同作用。** 住所提供居住条件，不默认生成居民；幸存者的接待与安置可由营地集会点等公共服务承担，是否需要专门建筑待定。交易站只有在实际承担对外往来时才参与招募；兵营负责军事训练或驻扎，不默认增加平民人口。主厅若仅承载管理界面，也不应默认成为所有操作都必须经过的门槛。

**探索、可见与安全范围需要分别定义。** 探索营地可以组织探索，观察设施可以揭示视野，灯塔可以驱雾或扩大安全领地；看见一片土地不等于已经能安全施工。灯塔是否持续消耗迷雾珠、失效后土地及建筑如何处理，需另写规则。前哨站以扩张为主时归探索扩张，以驻军防守为主时归军事防御。

**现有能力与未来建筑的价值要衔接。** 当前工人可以直接采树、采矿、采果，不能因目录出现伐木场就默认必须先建它。新增采集设施应有清楚的价值，例如管理补种、组织附近作业或开放特定资源。当前仓库和堆场使用共享库存，堆场增加两个装卸点；没有容量上限、独立分仓或跨仓调拨，不能将这些作为现有收益描述。

**同一设施可以承担多种作用。** 例如厨房兼供餐、主厅兼接待，早期这样合并有助于控制复杂度。归属取主要作用，详情列出附带能力。后续拆成独立建筑时，应让玩家获得新的布局或分工选择。

## 基础设施专项规则

当前已按用户授权在建造中接入基础路面与围墙首版；基础路面暂用+10%实验增速，围墙阻挡通行，出入口留缺口，详见[基础设施逐项设计](infrastructure.zh-CN.md)。本目录继续作为覆盖检查，具体规则以逐项讨论后的记录为准。

| 设施 | 建议的起步作用 | 需要先明确的规则 |
| --- | --- | --- |
| 道路 | 改善人员与搬运通行，居民仍可走未铺路地面 | 是否加速、是否优先走路、是否比较实际耗时而不是一味绕路、宽度是否影响拥堵 |
| 桥梁、台阶 | 跨越水面或高差，建立新的可达路线 | 两端连接、跨度和高差、允许通过的单位；随地图需求引入 |
| 围栏、院墙 | 划分场地或引导出入口；有畜牧后可考虑圈养 | 是否阻挡各类单位、能否跨越、是否有耐久和维修 |
| 院门、城门 | 在围挡上提供可控制的通道 | 允许谁通过、自动还是手动开关、关闭时如何处理途中人员和运输任务 |
| 普通照明 | 提供夜间可见性或氛围，具体效果另定 | 照明与驱雾的区别、是否消耗燃料、覆盖如何显示 |
| 供水等管网 | 仅在对应供给需求成立后连接设施 | 连接关系、容量、断供与维护；不默认加入现代城市管线系统 |

建议初期不强制所有建筑连接道路。若以后采用道路连接要求，需要在蓝图阶段显示入口和连接情况，并说明未连接是禁止建造还是暂时无法运营。道路的收益最终以真实行走与搬运表现验证。

**通行检查区分居民路线和防御意图。** 防御墙有意阻挡敌人，不应因此被认定为非法布局。对居民、施工人员和必需物流，应检查入口可达，围合时保留可用门；工地不能在最后一段完成时把自己的施工人员封死。战斗时主动关门造成停工，应给出受影响的任务和恢复办法。现有摆放检查尚未具备完整的城门与敌我通行规则。

**道路与墙体需要专门的铺设体验。** 后续考虑连续拖拽、端点吸附、转角、交叉口以及门与墙的衔接。预览应展示整段占地、有效与无效区段、总材料和预计施工劳动。重复经过已有路段或相同端点不能重复扣料；路面、墙体和门的重叠规则分别定义。

**分段设施需要明确何时可用。** 路段完成可以局部产生收益，桥梁可能需要全桥完成才允许通行，城墙缺口在补齐前仍可被穿过。具体规则确定后再实现，不能对所有设施统一按“完成一小段就生效”处理。

## 放置方式与运行方式

功能组不能代替建造操作规则。至少需要考虑以下形态：

| 放置形态 | 例子 | 操作重点 |
| --- | --- | --- |
| 单体 | 住所、仓库、灯塔、塔楼 | 占地、旋转、入口、工作位与覆盖预览 |
| 线段 | 道路、围墙、管线 | 连续绘制、端点和交叉连接、分段成本与施工 |
| 区域 | 农田、牧场、作业区 | 划定范围、可用面积、出入口；是否允许调整边界待定 |
| 两端连接 | 桥梁等跨越设施 | 两端有效、跨度限制、完成前后的通行关系 |

运行时还需区分被动提供能力、需要固定工作人员、按订单加工、持续消耗燃料以及提供范围服务等方式。这些作为设施属性；同一功能组内可以有多种运行方式。施工派工与完工后的运营派工分别说明，工人不能在没有提示的情况下被长期占用。

服务设施也不必一律采用圆形覆盖。住所可以按住户分配，供餐可以让居民实际前往，灯塔可以采用范围；采用何种方式由玩法决定，界面应清楚显示服务对象和能力上限。

## 建造后仍要考虑的规则

蓝图、运料、施工、完工属于建设阶段；正常运行、缺人、缺料、断路、产物积压、暂停属于运行状态。未解锁是可用性，受损是设施状况，不能把这些全部挤进一个互斥状态。玩家应同时看见主要问题、受影响的能力和可采取的行动。

升级、维修、搬迁与拆除是跨类操作，不另立建筑分类。进入对应范围时，需要明确：

- 升级或维修是否停工，原料和住户如何处理，是否需要运料与劳动。
- 搬迁是否真的搬走建筑，还是拆除后重建；不默认瞬间免费移动。
- 拆除取消哪些服务，是否返料，物品放在哪里；拆桥、拆门或拆路前提示通行影响。
- 设施损毁后人员、库存和在制品如何处理，遗址能否修复或清理。
- 暂停运营、暂停施工与停止供料分别控制什么；不能借暂停重复产出或退料。

耐久、火灾、维修、拆除和升级当前均未因为本目录而进入实现范围。

## 当前实现与建议验证范围

| 内容 | 当前状态 | 后续建议 |
| --- | --- | --- |
| 初始仓库、物资堆场 | 仓库为固定设施；堆场已能建造并增加共享库存装卸点，支持保存恢复 | 继续复用，观察位置与装卸能力的实际价值 |
| 食物生产与居民消耗 | 未实现；现有果丛仅有采集、运输和库存 | 优先接一种食物来源与消费规则，观察劳动分配和缺粮反馈 |
| 住所 | 居住用途未实现 | 结合居民规则接居住名额与入住，不默认自动生人 |
| 灯塔 | 扩张用途未实现 | 完成一次具有明确资源收益的扩张 |
| 道路 | 已接入基础路面格段铺设、实际运料施工、完工小幅增速及存档 | 根据试玩调整铺设、成本和增速 |
| 围墙、城门、塔楼 | 普通围墙已接入格段施工与阻挡；城门、塔楼和战斗效果未实现 | 围墙先验证场地分隔；军事防御与进攻验证配套 |
| 桥梁、管网与公共服务扩展 | 未实现 | 在地形或居民需求要求它们时加入 |
| 研究、贸易、装饰及复杂生产链 | 未实现 | 保留目录位置，是否制作取决于体验需求 |

原经营验证建议仍以现有物流、食物供需、住所和灯塔为主；道路作为可选择的布局验证，城墙和城门与战斗验证配套。新增分类没有自动改变开发顺序。若守城被确认为核心卖点，应在扩大制作前单独验证，不能由经营原型代替。

## 单项设施的设计记录

后续确定具体清单时，每项至少记录：

1. **目的与归属**：解决什么问题，主要功能组与附加作用，玩家如何判断建得值。
2. **获得与放置**：解锁或修复条件、放置形态、占地、地形要求、入口与连接规则。
3. **建造投入**：材料、施工劳动、可同时工作人数，分段建造如何计费和生效。
4. **运营投入与结果**：工作人员、输入物资或燃料、生产周期、产物或服务能力；数量为后续实验参数。
5. **物流与服务对象**：从哪里取料、产物在哪里等搬运、何时消耗，住户或服务名额如何分配；同一物资不重复计数。
6. **范围与通行**：覆盖对象、入口、敌我通行、视线与阻挡，相关内容按需定义。
7. **控制与异常**：运行开关、任务或供料优先级、缺人缺料断路等原因与恢复办法。
8. **生命周期与恢复**：必要的升级、维修或拆除规则；保存施工、住户、库存、在制品和能力状态，读档不重复结算。

## 建造菜单的表达建议

完整功能目录用于整理内容，实际菜单按当前可用设施展开，内容较少时可以合并展示。分类确定前不锁死十个顶层分页。墙、门和塔等配套设施应方便连续选用；搜索或快捷入口可以跨分类引用同一项设施。

建筑卡片优先说明用途，例如“物资堆场：增加两个装卸点”“道路：改善通行，具体收益按最终规则显示”。蓝图阶段显示建造成本和连接要求；完工面板显示运营投入、当前产出或服务、短缺和下一步行动。装饰品若只有外观作用应明确说明。

范围、可达性和加速等效果必须与真实规则一致。现有“稍后／普通／优先”仅决定工地供料，不能暗示同时提高生产或服务优先级。若以后引入拆除或修路模式，应明确显示正在操作什么，并支持取消。
