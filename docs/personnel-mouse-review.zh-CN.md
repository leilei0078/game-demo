# 人员左、右键交互审查

日期：2026-11-17。依用户要求，等待“02.2-建造模块设计（2026.11-）”本轮结束后开展。通过 `wait_threads` 确认该轮已完成，再读取最新代码并操作 Unity。

后续状态（同日）：用户明确了“左键框选后，左键点空白取消选择、点单人只选他”。现已实现此规则、队列开关与选择分离、头顶编号选择及避开模型；鼠标专项 `output/unity-selection/mouse-verification.json` PASS。下面保留审查时的原始问题与建议；全面改为资源／仓库左键只查看尚未实施。

## 结论

当前选人、采集和施工派工可用，但人员操作的主要风险是“想选择或查看，结果改了任务”。优先建议统一为**左键选择／查看、右键下令**，同时修复头顶编号命中和分开处理多选、任务追加。此次只做审查，未改玩法代码；下表是建议，尚非用户确认的规则。

## 优先优化项

### 1. 左键负责选择和查看，右键负责执行任务

目前左右键点资源、原仓库和地面都会下令；工地则左键查看、右键执行。同样一次左键，在不同对象上可能是安全查看，也可能中断当前工作。空地点选尤其容易与取消选择的意图冲突。

建议的普通模式规则：

| 对象／操作 | 左键 | 右键 |
| --- | --- | --- |
| 工人模型／头顶编号／底部名单 | 选中并查看；同一套选人规则 | 暂无跟随功能时提示“请点地面、资源或工地”，保留任务 |
| 空地单击 | 清除选择，人员原任务继续 | 所选人员移动 |
| 空地拖框 | 框选人员 | 不新增拖动命令 |
| 资源 | 查看数量、工作人数、可操作事项，保留人员选择 | 所选人员采集／搬货 |
| 原仓库／完工堆场 | 查看库存或建筑信息，保留人员选择 | 携货人员送货；空手者原任务保留并解释 |
| 未完工工地 | 查看材料和进度，保留人员选择 | 所选人员运料／施工 |
| 蓝图摆放模式 | 放置 | 退出当前摆放，不顺带向下面对象下令 |
| 拖图模式 | 拖地图 | 退出拖图，不顺带下令 |

右键在普通模式下不应被全局解释为“停止当前工作”；停止使用明确按钮／S，“本轮后结束”继续独立保留。触控板用户可继续使用面板中的明确任务按钮；如后续新增纯左键操作方案，应作为明确模式呈现，避免默默恢复混用。

### 2. 编号和模型共享选择命中，文字不能穿透成移动

优先检测实际绘制的头顶编号矩形，再检测模型；被避让移动后的标签以实际矩形为准。点击标签应选中对应工人，并拦截后面的地图命令。对树木、工地的标签也应采用一致原则，避免看得见的名称与可点击区域分离。

模型本身较小，密集站位及选中后标签重新排布使对应关系更难看清。可以扩大人员选择容差，并为悬停对象加清楚的轮廓／选中提示；避免只加更大的不可见点击区而造成邻人歧义。

### 3. 将“增加选择人数”和“追加后续任务”分开

`AppendHeld`目前由鼠标追加开关或Shift共同决定。场景点击和框选把它传给 `Select`；底部名单只看Shift。因此“追加下令：开”不仅控制队列，还改变场景选人规则，底部选人却不跟随。

建议鼠标“追加下令”仅影响右键／面板任务队列；Shift+左键统一增加／移除所点工人，Shift+拖框增加选择；Shift+右键追加任务。场景、头顶编号、底部名单遵循同一规则。纯鼠标多选可用拖框；如需要逐个人员增减，另设清楚的“多选”控件。当前选择只能加入、不能逐项减选的问题也一并处理。

### 4. 在鼠标附近显示“这次右键会做什么”

现有接受人数和原因反馈有价值，应保留。建议悬停时明确写“右键：安排所选2人伐木／施工”或“Shift+右键：加入后续”，同时表达拒绝原因。头部距离操作位置较远，原型界面整体按钮较密；优先把正在操作的对象和人员数联系起来。成功／部分接受／失败继续用文字区别，避免仅依赖圈的颜色。

暂停时能选人和查看，但不能安排任务，画面已有说明；是否允许暂停规划后统一执行是后续体验选择，不能当作现成缺陷直接修改。

## 可保留的行为与验收边界

- 左键工地查看保留人员选择，右键明确改派；有效反馈包含接受人数。
- 摆放模式右键只取消模式，没有再给下面的资源下采集命令。
- 此轮实点底部名单、追加开关及查看面板，没有发现界面点击向地图下令。
- 本轮没有重新验收持续拖拽、实体触控板、多显示器、其他DPI、物理Shift或完整无障碍操作；旧事件流通过不能替代这些设备测试。截图中的标签小、低对比文字和色彩提示是可见风险，未宣称完整可访问性达标。
- 临时运行记录读取曾因误写资源枚举 `Fruit` 而在eval编译阶段失败，改用现有枚举数值后查询成功；未修改源代码，最终Console 0错误／0警告。
