# 建造操作与采集运输联动审查

2026-11-17。Unity本地几何原型；依据本轮实际运行、鼠标操作、Input System事件和截图审查。

后续已完成首次建造引导、工地供料顺序与实际1280×720/1366×768视口检查，当前结果见 `guidance-priority.zh-CN.md`。下文保留场地打磨当时的审查证据和边界，历史待办以新记录为准。

## 完成的改动

- 场地22×14扩大为36×26米；中键拖图、指向缩放；“拖动地图”提供左键拖动替代，“回到基地”复位。
- 蓝图占地轮廓、黄色双入口/朝向箭头、合法/非法文字原因；R或按钮旋转，右键/Esc取消。投影到地面，避免树顶/建筑顶部影响落点。
- 预先用保守通行网格检查新障碍，不切断原本连通的建筑入口、资源工作位、工人与待命区；实际行走仍使用NavMesh。原练习通道仍保留。
- 派1/2名空闲空手无队列工人；保留手动选人派工。显示运输/施工/等待人数，区分仓库缺料、在途、材料齐备、路线受阻。
- 左键工地查看，右键或面板派工，避免查看时抢走采集工。界面拦截地图点击/滚轮；拖选在界面释放时取消；失焦重置拖动。面板增加对比度，地图标签避让展开面板。
- 写入v2存档，保存镜头焦点与扩大场地；兼容真实v1手动存档，原文件未覆盖。暂停时道路更新也能结束。

## 流程审查

1. **规划与摆放：可用。** 实点打开面板、无效红色轮廓和具体原因、合法蓝色轮廓与黄色入口、放置均通过。界面按钮不穿透。仍需引导玩家理解入口需要留路；保守检查可能拒绝部分狭窄布局。
2. **派工和补料：可用。** 实点派2名空闲工人通过，零库存显示木18/矿6缺口。三工地联动实际采集、领料、运到、施工通过。多工地共享余额没有优先级，库存不足时玩家仍需决定先建哪座。
3. **保存继续：可用。** 运输中存档恢复，真实退出/重进Play Mode后继续三座工地至完工，材料木324/矿144/果90守恒，装卸点恰好9个。当前仍为单槽手动保存，读取会替换未保存世界。
4. **完工和查看：可用，有后续打磨空间。** 完工提供实际装卸入口；旧建造回归包含新入口入库、取消退料、暂停改派、堵路恢复、旋转和任务交接。密集单位标签仍会拥挤；完工用途的表达可在新增生活建筑时一起完善。

- `output/unity-polish/integrated-verification.json`：三工地从零库存施工、在途读档、v1兼容、v2镜头/暂停/材料/任务恢复，PASS。
- `output/unity-polish/restart-verification.json`：真实退出/重进Play Mode恢复三座未完工建筑并全部完成，PASS。
- `output/unity-polish/mouse-verification.json`：鼠标事件点选、12人框选、中键/左键拖图、界面释放取消、滚轮拦截、摆放缩放、右键取消、左键查看不改派、右键派工，PASS。
- 原采集回归 `output/unity-polish/gathering-regression.json` PASS：库存102、12人72件、携货改派/一趟/堵路重试恢复/队列/统计守恒。旧实时超时但随后完成，测试改模拟时间并保留3倍实时时间看门狗后通过。
- CUA原生鼠标：建造/面板、点选工人、滚轮、无效与合法预览、放置、派2名空闲工人已通过。工具的原生拖拽未稳定产生持续移动；框选/拖图的通过证据来自Input System事件流，不能等同于所有实体鼠标/触控板实测。R/Esc/Shift物理快捷键本轮未逐项复核。
- 截图显示对比度改善，非法落点同时有文字原因，非仅靠颜色。小窗口/高DPI、多显示器、色觉与读屏尚无完整验收；不宣称无障碍合规。
- 恢复重建未完成时的瞬时实体总量不应作完成态守恒断言；测试已在Ready后检查，逐帧正常运行继续检查。

## 后续优先级

1. 一段可玩引导：先采木矿、再放蓝图、派工、观察缺料与完工收益，减少一次看到全部按钮的负担。
2. 工地优先级和补料提示：共享库存竞争时，让玩家明确哪座先领料，补采资源可从缺口直接定位。
3. 真实小窗口与输入设备验收、可分发中文字体；逐步整理原型按钮密度。

当前不急于堆更多建筑种类。先用这一版确认分工与施工节奏，再接食物/住所/灯塔的具体用途，更容易看清经营循环是否成立。
