# 本地保存与继续

2026-11-17，本地单槽检查点（当前写入v4，兼容读取v1/v2/v3）。Unity客户端本地落盘，尚未连接后端数据库。

## 使用

运行中点击右上角“保存”。下次进入Play Mode后点击“继续存档”，回到保存时刻；按钮会在正式存档或备份存在时启用。保存和读取均可在游戏暂停时使用。当前采用手动保存，不自动保存退出后的新进展，不计算离线产出。

文件位于 `Application.persistentDataPath/WorldSaves/world-v1.json`，保存成功会显示实际路径和保存时刻。上一版为同路径 `.bak` 文件。读档会替换当前运行世界，未保存进展不会保留；首次进入仍从初始场景开始，玩家自行选择继续。

## 保存内容

建造顺序保存在 v4 的可选字段 `priorityPosition`，自动排入的工人后续建造任务标记为 `autoBuild`。旧档没有排位时，沿用原优先档并按建筑编号排序；无法区分来源的旧队列视作手动指令，保留原有次序。在途建材仍绑定原工地。

新放置蓝图的待派工批次保存在 v4 可选字段 `autoCrewGroup` 中；已有人员接单后由工人的当前任务/队列恢复。旧档没有此字段时保持原有手动派工状态，避免读取旧世界就改派人手。

- 存档版本、地图规则标识、物流配置、世界时间、暂停、路障、镜头缩放/焦点、累计采集入库趟数、首次建造引导进度及收起状态。
- 资源稳定ID、类型、位置、原始/剩余数量；包含已经搬空和仍待搬运的退料箱。
- 建筑稳定ID、设施类型、位置与旋转、供料优先级、已到材料、施工劳动、工地暂停、完工与取消状态。
- 工人稳定ID、位置、货物类型/数量/锁定单重、退料标记、在途材料对应工地、当前任务ID与目标、原采集目标、一趟/续采、先入库再改派、后续队列及其任务ID。

稳定ID为本世界内编号，不依赖Unity InstanceID；恢复后新实体和任务继续使用未占用编号。此实现尚非多人世界ID系统。

## 恢复规则

读取前先验证文件校验值、版本、实体ID和引用、数值范围、施工成本及逐类材料总量。错误文件不替换当前世界。正式文件损坏时尝试上一版备份，并明确显示备份恢复；若两份都无效，则保留当前世界。

恢复重建资源、建筑及已完工的装卸点，再绑定工人和任务，等待导航障碍更新后继续。工作位、卸货位、排队与路线重新申请，不保存旧NavMesh路径。

尚未采出的批次取消预约，采集进度归零；已经采出的货物保持原数量与重量。仓库装卸和工地卸料若尚未结算，重新开始该动作；已结算的转移在快照中保持，不再补发。施工劳动进度保留。手动停止的携货工人仍待命，不会在读档后擅自送货。

采集效率统计是本次观察窗口，读档后重新开始；不会将历史入库量当成当前库存。累计入库趟数独立保存。仓库仍采用共享库存。

## 写入保障

将整个世界写入带SHA-256校验的JSON封套，先写同目录 `.tmp` 并刷新文件，然后首次移动或原子替换正式文件。替换时保留上一版合法正式文件为 `.bak`；如果正式文件已经损坏，后续保存保留原有有效备份。读档忽略未提交的临时文件。

校验用于检测损坏，不提供防作弊功能；当前没有账号、云同步或数据库事务。v1存档在扩大场地中恢复，镜头焦点默认为基地；v1/v2工地供料默认为普通，引导从当前进展重新判定。当前新保存写入v4，延用v2地图标识，保留v3的优先级与引导状态，并增加设施类型（堆场/路面/围墙）；按类型校验成本、劳动、完工和在途分配，旧版本建筑默认为堆场。读档重建道路导航区域，只有堆场重建装卸点。引导到达保存步骤后，只有实际写入成功才标为完成。文件名world-v1.json为保留旧单槽路径，内容版本由JSON决定。文件原子替换已在当前macOS环境验证；尚未完成Windows/Linux独立构建和断电实机测试。

## 验证入口

- 空库存新场景 `SaveVerification.Start()`：真实采集、运输、施工、退料的多阶段存读检查。每个检查点连续恢复两次，并核对物资、在途分配、实体/任务ID及队列。
- 完成上述检查后退出并重新进入Play Mode，调用 `SaveVerification.RestoreAfterRestart()`：从磁盘恢复已完工/已取消/退料世界，再读半成品建筑并继续建完。
- 输出 `output/unity-save/save-verification.json` 与 `restart-verification.json`。测试使用独立文件，正式手动保存槽不受影响。
- 新增 `GuidanceVerification.Start()` 与真实退出/重进后的 `GuidanceVerification.RestoreAfterRestart()`，验证v3在途材料/优先级/引导恢复及真实v1、v2兼容。结果见 `output/unity-guidance/guidance-verification.json`、`restart-verification.json`；本轮保留原正式v1手动槽。
