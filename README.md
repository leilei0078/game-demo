# 林间驿站 · Wayfarer's Rest

用 Blender 原生几何搭建的中世纪奇幻场景 demo。美术方向参考《阿尔比恩 Online》的斜俯视视角、厚实轮廓、克制的土色配色和风格化低多边形造型；场景及模型为本项目原创。

## Unity 接入

玩法移植工程为 `UnityGatheringDemo/`（Unity 6.3 LTS 6000.3.27f1，Built-in），与树木资产工程独立。采集场景已生成保存，Unity 已进入 Play Mode；实际点击完成选人、伐木、运输与入库，12 人多资源采集运行及资源守恒检查通过。已补下令人数/失败原因、可取消任务队列、一趟采集、等候位置及路障移除后自动恢复，配套 Play Mode 回归检查。更完整的中断矩阵、引导与长期稳态吞吐量测试仍待完善。详见 `UnityGatheringDemo/README.zh-CN.md`。网页仍作为规则对照。

Unity 现已加入效率统计面板和十组采运对照，覆盖重量、容量、采集速度、步速与人数，原始数据在 `output/unity-gathering/efficiency-benchmarks.json`。后端/存档方案在 `docs/backend-database.zh-CN.md`，SQL 草案在 `backend/database/001_initial.sql`；尚未部署或接入数据库。

## 当前试玩：采集调度

运行 `npm run dev`，打开 **http://localhost:5173/play.html**。当前先打磨采集操作，收起建造、招募与战斗入口，地图没有敌人。领主保留选择与移动，工人使用简单模型。

- 顶部引导依次体验选人派工、自动运输入库、结束本轮、恢复原采集。引导可跳过，始终允许手动操作。
- 左键点选或拖框选人；选人后直接点击地面移动、资源采集、仓库送货。点其他工人切换选择，拖框多选，Shift 可追加命令；Esc 退出下令模式，再按可取消选择。查看详情使用“查看资源”后点资源，或 Alt + 点击资源；未选人时点资源也可查看。右键下令继续保留。也可用资源详情的“安排所选人员”或快捷伐木、采矿、采果、搬货按钮。
- 工人自动采集、背货、运送、排队卸货、返回资源点。只有卸货才增加库存；所选人员的携货量单独显示。资源有四个工作位，主仓库有三个卸货位。
- “本轮后结束”：完成这一份采集并入库后待命，取消后续命令；已有货物时直接送完，不再采下一份。“立即停止”或 S：原地停止，保留货物，清空队列。“送回仓库”：直接送现有货物后待命。“恢复原采集”：从上次资源恢复，资源采空则禁用。
- 携货改派其他资源时先入库再执行；未完成的采集进度取消，不扣资源。资源采空默认待命，可开启“采空后续采”；明确排队的后续命令优先。
- 固定障碍自动绕行，人员相互避让。持续十秒未向目的地推进，或路径走不到目的地时，显示“路线受阻”并保留任务、携货。每隔三秒尝试重算路线，最多三次；之后可手动“重试路线”、改派或停止。正常的工作位和卸货位排队显示顺位及等待时间；受阻人员会释放工作位与卸货位预约，重试时重新选择可达位置。点击“选受阻”可定位这些人员。工作概览内有可开关的练习路障，可以实际体验封路与恢复。

鼠标指向目标会预告点击动作；采集、送货、移动分别显示目标反馈。重复点击同一资源不重置采集进度、产出预约或工作位；重新下达当前任务会清空后续命令。Shift 连点不会重复追加队尾相同任务，后续队列上限 16 条。混选人员点仓库时仅派携货者送货，不打断其他人的工作；空载点击仓库、点击采空资源或障碍位置会说明原因并保留原任务。

采运参数可按需展开调整。默认每趟最多 6 件、18 kg，木材 2 kg/件、矿石 3 kg/件、果实 0.5 kg/件。每趟数量取件数上限、重量可容纳的整数件数、剩余库存中的最小值；多人不会重复预订同一份产出。空载速度 2.9 m/s，移动上限 = 空载速度 × (1 − 0.3 × 负重比例)，减速最多 30%；避让、转弯和排队会进一步降低实际速度。采集按每件耗时累计，再除以采集效率；卸货耗时 = 0.3 秒 + 每件耗时 × 件数。重量影响搬运，资源作业类型决定采集难度。

每份工作开始时锁定件数、重量和耗时；中途调参不会改变已经开始的这一份，也不会改变已背货物的重量。空载速度与负重比例使用新参数即时计算；降低载重上限后旧货不丢弃，速度按满载处理，下趟遵守新上限。停止会释放未完成的产出预约，不扣除资源。面板显示各类资源下一趟的预计件数、重量、采集时间和移动上限；累计入库件/分包含起步、等待与停工，属于实际观测值。

`npm run check:logistics` 运行固定地图上的重量、件数、采集、移动、卸货、距离、人数及组合对照，报告保存为 `output/workers/logistics-comparison.md` 和 `.json`。它验证规则关系，不代表最终平衡数值。

`npm run check:collection` 检查结束、停止、恢复、改派、资源守恒、临时封路恢复、自动重试上限、人群与浏览器交互。浏览器检查需要先启动开发服务。采集规则在 `src/workers/sim.ts`，引导在 `src/workers/campaign.ts`，画面与输入在 `src/workers/main.ts`。原经营及战斗规则暂存，当前页面不启用。

## 保留演示：小兵移动与工作

运行 `npm run dev`，打开 **http://localhost:5173/workers.html**。有 12 个简单几何小兵、一块网格场地和资源点，初始全部待命。

- 左键选人、拖框多选，Shift 加选；底部编号可单选，1–3 召回编组，默认每组四人；Ctrl + 1–3 保存当前选区，或点击“全选 12 人”“选空闲”。右键地面移动，右键资源工作；也可以点击“移动”或“采集 / 砍伐”，再点目标，触屏使用这一方式。
- 树木砍伐、矿石开采、果丛采集、木箱装货；每次最多 6 份，背货运到仓库并卸货后才入库，然后自动继续。源头余量与背包货物都可见。
- “停止”保留已背货物并清除排队指令；“送回仓库”卸货后离开卸货口再待命。移动会取消工作；背货时改派新资源，先运完现有货物再去新资源。空格暂停，重置重新开始。
- 寻路采用 0.5 米网格 A*，绕开仓库与未采空资源。选中单位显示路径。单位使用预测避让、侧向绕行与最小间距限制；目标位置保持分散，路口等待过久会重新寻路。每个资源点最多同时四人作业，多余工人等待工作位；仓库三个卸货位按到达请求顺序分配，卸货后离开，避免占住入口。Shift + 右键追加移动、工作或运输任务；采集任务在资源耗尽后结束，之后执行下一条。
- 快捷派工：选人后点击“伐木 / 采矿 / 采果 / 搬货”，伐木会参考两处树木的人数分配；指定具体资源仍用右键。默认工作任务持续到指定资源采空；开启所选人员的“采空后续采”后，会转往同一工作类型的可用资源，显式排队的命令优先执行。停止或移动会接管当前工作，续采不会让空闲人员自行开工。
- “自动分工”仅分配所选人员，参考已有任务按伐木 4、采矿 3、采果 3、搬货 2 的比例补位；耗尽的资源类型自动排除。“选等待”筛选等待工作位或卸货位的小兵。续采开关支持显示所选人员的混合状态，头顶 ↻ 表示已开启。
- “工作概览”按需展开，显示每处资源余量、正在工作和实际停下排队的人数；“＋”从无货空闲人员补一人，“−”优先撤回等待/未携货人员，携货撤回先完成入库再待命。点资源名称可选择该处已分配人员。
- 框选过程中实时高亮将被选中的人员。M 移动、G 工作、I 选空闲、F 聚焦所选；工作指令会退出“平移”模式。移动中的等待人员计入移动/运输，到位排队才计入等待。
- 底部显示空闲、移动、工作、运输、等待人数；编号下沿和头顶标签使用对应颜色。移动时显示路径及落脚点；单选时可查看后续任务、清空后续任务而保留当前命令。
- 滚轮或右上角按钮缩放，中键拖动或方向键平移，Home / “全景”复位。手机可使用缩放按钮查看小兵，点击“平移”后单指拖动画面，再次点击退出平移。默认三组使用蓝、绿、紫上衣区分；自定义编组不改变服装。
- 代码在 `src/workers/`，不使用外部模型。`npm run check:workers` 检查模拟规则与浏览器操作（先启动开发服务），截图在 `output/workers/`。

## 保留版本：青岬领 · 边境战役

运行 `npm run dev`，打开 **http://localhost:5173/rts.html**。领主始终只有一位。农夫、枪卫和弓手独立接受订单，新兵在兵营外待命。胜利条件是摧毁东北的赤牙营寨；领主大厅失守则本局结束。

- 左键点选或拖框、Shift 加选，双击单位或按 1–4 选择同类型。右键地面移动，右键资源派工，右键敌人进攻。也可以先点击指令，再点击目标。Ctrl+5–9 保存选区，5–9 召回。
- 只对选中的农夫派工：耕作、采金、伐木、施工；送回大厅后才入库。建造兵营后可招募枪卫和弓手，农舍扩人口，哨塔自动防守，伐木场增加运量，锻造坊提升伤害。
- 移动命令到达后待命；部署命令使士兵驻守目标周围，在附近迎敌后回到岗位。WASD 始终移动领主，Q 激励附近部队，大厅附近可购买战马。方向键、中键拖动、小地图可转移视角；滚轮缩放、Esc 暂停。
- 建筑按 1 米网格吸附；兵营 6×5 格、农舍和哨塔 4×4 格、锻造坊 5×5 格、伐木场 5×4 格。放置时显示占地绿格与受阻红格，右键或 Esc 取消；建成及施工中的矩形占地都参与寻路，一格通道可通行。占地表在 `src/rts/grid.ts`。
- 玩法规则在 `src/rts/sim.ts`，战场和操作入口在 `src/rts/world.ts`、`main.ts`。本地单人战役，刷新会重开。`npm run check:rts` 检查局内规则及浏览器操作（需先启动开发服务）。
- Blender 源资产 `output/rts/FrontierRTS.blend`。运行 `scripts/create_rts_assets.py`、再运行 `scripts/rts_catalog.py`（均在 Blender 后台）可重建模型和头像。大厅在网页中复用原驿站的详细建筑；军营、农舍、箭塔、单位和战马使用新的 GLB。模型检查见 `output/rts/asset-qa.json`，农舍与伐木场仅有内部横梁与门楣接触面提示。

## 旧版：荒野委托

运行 `npm run dev` 后打开 **http://localhost:5173/adventure.html**。斜俯视相机跟随旅人，在驿站两岸完成一个单人委托：采集 3 份雪松木、2 份铜矿石，击退 2 只野猪，再回篝火旁按 F 领取 120 银币。

- WASD / 方向键移动；点击地面寻路，点击资源或野猪自动靠近并行动；滚轮缩放。
- F 采集、篝火休整或交付，空格挥剑，Q 回旋斩，E 疾行，R 使用药剂；Esc 暂停。技能消耗体力并有冷却时间。
- 野猪有警戒范围、追击、蓄力攻击和恢复间隔；负伤倒下后回驿站，保留本轮采集进度。
- 手机显示方向按钮和动作栏。失去窗口焦点或切换标签时自动暂停。

玩法入口为 `src/play/main.ts`，规则和四分之一米网格 A* 寻路位于 `src/play/simulation.ts`，Rapier 胶囊角色、河岸、桥面坡道、资源和房屋碰撞位于 `src/play/physics.ts`。这是本地单人原型，未实现联网、交易或跨刷新存档。装饰森林为场景边界，游戏区域内资源有独立碰撞。

角色、野猪、铜矿、雪松和树桩由本机 Blender 5.2.2 后台进程生成，源文件为 `output/play/WayfarerGameplay.blend`，生成脚本为 `scripts/create_play_assets.py`，运行模型位于 `public/models/play/`。这些新增资产合计 48 个网格、1,632 个三角面，采用纯色 PBR 材质；无图像纹理，因此几何检查明确关闭 UV 检查。`output/play/qa.json` 保存逐部件及组装检查结果，多角度材质和线框审查图也在同目录。原驿站 Blender 文件继续作为环境来源。

重新生成与验证：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python scripts/create_play_assets.py
npm run build
# 开发服务运行后执行：
npm run check:play
```

可玩版独立于原场景预览；构建会将两个入口一起输出。首次加载包含本地 Rapier WASM 物理引擎，无 CDN 依赖。

## Web 交互预览

新增 `/trees.html` 树木风格对比页：五种真实 Blender 模型，新增参考图方向的柔冠童话松，支持单树旋转、线框、三级 LOD，以及 25/100/300 棵分区实例化森林。当前雾林与原版均保留。Unity 6 Built-in 已实际导入、核对面数并渲染验证；URP 提供材质重建工具。完整说明位于 `UnityTreeStudies/README.zh-CN.md`，可导入包为 `public/downloads/TreeStudies.unitypackage`，含 Blender 源文件的完整包为 `public/downloads/UnityTreeStudies.zip`。树木生成脚本为 `scripts/create_tree_studies.py`，运行后用 `node scripts/optimize-trees.mjs` 合并共享纹理，网页实际加载约 2.4 MiB 的单一 GLB。`node scripts/check-web.mjs --trees` 检查模型、交互、LOD、实例化和手机布局，记录保存在 `output/tree-studies/`。构建现在包含三个页面入口。

```sh
npm install
npm run dev
```

打开终端显示的本地地址（默认 `http://localhost:5173`）。模型、脚本和图标全部随项目提供，运行时不依赖 CDN。

### 保留版与雾林参考版

- `/`：继续保留当前的风格化场景，源码和模型未被参考版覆盖。
- `/versions/classic/`：开始制作参考版之前冻结的完整可运行版本，包含独立打包的脚本、模型和图标；新版本右上角“原版”可直接打开它。
- `/mistwood.html`：参照用户提供的密林木屋图片制作的独立 Web 版本，入口及实现位于 `src/mistwood/`。高大的树干与相接的根系、枝条取代原先的锥形树冠，使用带透明针叶轮廓的枝簇；林地增加蕨类、落叶、树皮苔藓。木屋、石块、屋瓦和木桥添加风化表面，补给旁新增有立柱、斜撑、椽子和连续屋板的雨棚。近景保持清晰，远处冷雾包围营地，暖灯与篝火作为视觉焦点。保留旋转、缩放、昼夜切换、物件介绍和减少动态设置。

参考版复用原来的木屋 GLB，并在 Web 中生成森林、雨棚和表面细节；没有替换或修改 `output/wayfarers_rest.blend`。参考图用于构图、材质和氛围方向，交互画面仍为实时三维渲染。原版源码与 Blender 文件的归档为 `output/versions/classic-source.tar.gz`，关键文件校验值为 `output/versions/classic-manifest.json`，参考图片存于 `output/versions/mistwood-reference.png`。

`npm run build` 同时输出两个入口和冻结版；`node scripts/check-web.mjs --mistwood` 检查原版文件校验值、森林几何、加载与着色、视角、点击、昼夜、减少动态、手机布局和冻结版访问。参考版目前有 130 棵树、17,820 个批量绘制的针叶枝簇、280 株蕨类和 2,600 片落叶。多角度及昼夜截图、检查记录保存于 `output/mistwood/`。针叶的法线/深度预处理也遵循透明轮廓，避免在雾里产生方片；木纹按屏幕像素足迹过滤，避免近细远闪。

- 拖动旋转，滚轮缩放，右键拖动平移；触屏可用单指旋转、双指缩放与平移。
- 底部切换全景、小屋与营地视角，开启自动环绕或复位。
- 点击小屋、营地、树林、木桥和补给物品查看介绍。
- 右上角切换昼夜；篝火、火星和溪流微光带有轻微动态。
- 快捷键：`1` / `2` / `3` 切换视角，`R` 复位，`N` 切换昼夜，`Esc` 关闭介绍和帮助。

网页使用 Three.js、TypeScript 和 Vite。Blender 模型以 GLB 格式加载，静态网格按区域与材质合批以减少绘制调用；网页灯光为实时灯光，视觉效果与 Blender 的离线渲染有差异。这是可交互的美术场景预览，不包含行走和战斗玩法。

Web 当前使用冷调奇幻配色：森林与草地偏青绿，石头和阴影偏蓝灰，溪流与外围雾为冷青色；木屋保留柔和的暖棕与砖红，窗灯和篝火作为暖色焦点。`src/palette.ts` 集中管理灯光、曝光、雾色及 GLB 材质的颜色调整，原有砌石色差继续保留；地表、水面和草簇的程序颜色位于 `src/landscape.ts`。昼夜切换沿用这一配色，夜间保留地形和物件的可辨度。这次调整只作用于 Web，Blender 原始材质不变。调整前的全景、营地和夜景截图保存在 `output/palette-before/`，当前截图位于 `output/web/`。

白天额外减轻营地中心的空气雾、减少冷色补光，并在 `src/color-output.ts` 的现有输出步骤中提高中间调饱和度和对比度，避免 AgX 后的画面发灰；亮部使用较小的饱和增益，保持火焰和水面反光柔和。该调色随入夜淡出，夜景沿用原配色；外围遮蔽用雾继续保留。白天调整前的截图位于 `output/daylight-before/`。

河水与草地在 `src/landscape.ts` 中使用连续的世界坐标程序材质：水面包含深浅色、水底卵石纹理、动态波纹和预过滤天空反射，岸边从湿土过渡到草色；草地使用斑驳色层和批量绘制的草簇。无需额外下载贴图。这些增强作用于 Web 预览，Blender 源文件保留原始材质。系统开启“减少动态效果”时，水纹保持静止。

Web 版篝火由 `src/fire.ts` 绘制为小范围体积火焰，替换原先的发光尖锥和硬边火星；火苗根部固定在柴堆中，上部随上升扰动弯曲、分叉，橙红色外焰向金黄火心过渡，配合细小柔光火星及克制的火光。火焰使用场景深度在木柴、石块等不透明物体前截断，支持旋转视角；系统开启“减少动态效果”时，火焰和火星均静止。该效果只用于 Web，Blender 中保留原始静态火苗。`node scripts/check-web.mjs --fire-only` 检查实际火焰像素、完全遮挡、昼夜、多角度与减少动态设置，截图和记录保存在 `output/web/fire-*`。

`src/forest.ts` 为 Web 版添加连续草地、延伸的河流和道路，以及批量绘制的外围森林，使营地融入林地。`src/mist.ts` 使用场景深度和低步数体积积分生成空间雾：远处树林逐渐失去对比度，低处带缓慢流动的薄雾，营地中心保留清晰度。雾层随昼夜变色；系统开启“减少动态效果”时停止流动。这些 Web 环境增强不修改 Blender 源文件。

Web 版道路由 `src/roads.ts` 统一定义主路和通往木桥的弯曲支路，将两条曲线合并成一张有符号距离场，在草地材质中直接绘制土路。路口只有一层地面，路色、碎粒与草土过渡连续；旧版两张道路条带不再加载，修复了桥分组漏用土路材质造成的纯色矩形。靠近木桥的最后 0.815 m 有向桥面抬升的土坡（896 个三角面，最高处 y=0.586 m），道路掩码也用于草簇和林木避让。该修正作用于 Web 环境，保留 Blender 的原始地形道路。`node scripts/check-web.mjs --roads-only` 可验证支路连续、旧条带移除、共用材质、篝火净空、桥头坡道法线与高度；近景、俯视、桥头截图及 `road-audit.json` 保存于 `output/web/`。

墙脚砌石的 Blender 源模型由 `scripts/masonry.py` 生成：8 mm 接缝、8–10 mm 小倒角、上下错缝和交错转角，六种接近的暖灰石色，后方有连续砂浆芯。`scripts/refine_masonry.py` 可单独更新已有场景，运行几何检查并生成材质、线框的多角度检查图；更新前的源文件备份为 `output/wayfarers_rest_before_masonry.blend`。本次检查覆盖 55 个部件、共 2,420 个三角面，各部件均为 44 个三角面；无重叠闪面、悬空、反向法线或退化面错误。唯一高度提示已接受：台阶底部为 z=0.25 m，略埋入场景 z=0.27 m 的地面，属于有意接地。完整记录为 `output/masonry-qa/report.json`。

`npm run build` 执行类型检查并输出静态站点到 `dist/`。部署时上传整个 `dist` 文件夹，需使用支持 WebGL 2 的现代浏览器。

`scripts/clearance.py` 统一修正小屋周围的布局，完整生成脚本也会调用它：木桶移出墙脚，两个桶之间留约 18 cm，后桶与货箱之间留约 13 cm，箱子与围栏留约 8 cm；柴堆移到箱子右边并落地。屋旁四棵松树调整位置与冠幅，三组石块及邻近灌木避开房屋和围栏。`scripts/fix_intersections.py` 可对现有源文件执行相同的幂等修正，修改前备份为 `output/wayfarers_rest_before_clearance.blend`。

此次几何检查覆盖 119 个部件、3,216 个三角面（每部件 8–96 个三角面），全部通过。40 项额外检查验证补给物间距、附近植被与建筑/围栏的三角面相交情况，以及移动道具、树干的地面支撑。`output/clearance-qa/geometry.json` 保存每部件面数及检查记录，`clearance.json` 保存间距与相交检查，另有材质和线框的多角度检查图。接受的提示限于：场景地面为 z=0.27 m 而非检查器默认的 z=0；石块、灌木有意埋入地面；上下货箱接触处保留了隐藏的封闭面，便于独立编辑。树冠层叠、梁柱连接和上下堆叠属于有意连接，本次检查不代表全场景的任意物体都零相交。

招牌支撑由 `scripts/sign_support.py` 生成：墙面安装板及螺栓 → 悬臂与斜撑 → 横杆 → 两个闭合吊环 → 吊杆 → 招牌顶部固定座。`scripts/fix_sign_support.py` 可单独修复现有源文件；修改前备份为 `output/wayfarers_rest_before_sign_support.blend`。此前两个吊杆与悬臂横向错位、缺少横杆，属于建模连接遗漏。修复后，16 个部件、1,226 个三角面、4 种材质通过几何检查，并以 2 mm 接触容差检查整条支撑连接图：安装板接触真实墙柱，所有招牌部件均可沿接触链追溯至安装板。记录和材质/线框多角度图保存在 `output/sign-support-qa/`。唯一接受的提示为招牌离地 z=1.89 m，这是壁挂结构的正常高度。这里建立的是静态模型的支撑关系，Web 预览仍未启用刚体模拟；网页检查额外核对了导出后的吊环、吊杆和固定座对齐，以及正面、侧面近景。

三扇窗由 `scripts/windows.py` 重建，`scripts/refine_windows.py` 可单独更新现有场景，备份为 `output/wayfarers_rest_before_windows.blend`。墙体切出约 26 cm 深的真实凹槽，木窗扇比外框前沿内退约 11 cm；14 块独立灰绿玻璃使用四种接近的色调与粗糙度，另有窗扣、内部暗衬与窄布帘、带向外坡度的石窗台。侧墙竖梁及斜撑避开玻璃。Web 中玻璃带天空反射、部分透射、边缘积尘及轻微粗糙度变化，白天只保留极弱自发光，夜间才逐渐增加有明暗变化的暖光。程序表面变化位于 `src/windows.ts`，Blender 中保留标准 PBR 材质。

窗户共 44 个部件、3,428 个三角面，复用 10 种材质；每扇前窗 1,068 个三角面，侧窗 1,292 个。几何检查同时覆盖切洞后的主墙和三根调整的木梁。18 项补充检查确认墙体位于每块玻璃后方约 15 cm、窗框实际接触墙体、侧墙木梁不穿过玻璃。报告及材质/线框多角度图保存于 `output/windows-qa/`，网页昼夜近景保存于 `output/web/windows-*.png`。接受的提示仅为壁挂窗户/墙体不在 z=0，以及静态平面墙面保留 boolean 后的多边形（导出时三角化）；未发现悬空、闪面或法线错误。

`npm run check:web` 使用本机 Chrome 进行加载、视角切换、昼夜、拖动、缩放、点击介绍和手机布局的浏览器检查，截图保存在 `output/web/`；运行前需先启动开发服务。脚本中的 Chrome 路径可按操作系统调整。

修改 Blender 场景后，重新导出网页模型：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python scripts/export_web.py
npm run optimize
```

原始 GLB 写到 `output/web_source.glb`，优化版本写到 `public/models/wayfarers-rest.glb`。

## 文件

## 查看与编辑

用 Blender 打开 `.blend` 文件。默认使用主相机构图；按小键盘 `0` 切换相机视图，中键旋转视角。右侧 Outliner 按地形、小屋、植被、道具、营地和灯光分组。

场景中还有一台 `02 • Camp detail` 相机，可选中后按 `Ctrl + 小键盘 0` 将其设为活动相机，查看营地细节。按 `F12` 重新渲染。

所有模型和材质保存在同一文件内，无需下载贴图或安装插件。篝火是静态造型；此交付是可编辑的 3D 美术场景，不含游戏逻辑或动画。

