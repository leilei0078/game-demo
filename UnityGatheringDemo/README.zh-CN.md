# 采集调度 · Unity 移植首版

**仓库存放比例：** 点击顶部「仓库」，拖动滑杆分配木材与石料的存放空间。默认木材 65%、石料 35%，两者各至少保留 20%。实际入库后，木料和石块在原仓库内分别显示；调整比例不会改变库存、入库上限或装卸位。比例随手动存档保留，旧档缺少该设置时使用默认比例。

**1 号工人：** 在主场景 `Assets/Gathering/Scenes/GatheringDemo.unity` 按 Play，选中待命区里穿浅灰橄榄短衫、黑短裤的居民，点树即可采木回仓。1 号使用人物模型，其他 11 人保持占位外观。去采木时背空木架，回程用绳索固定仓库同款短原木，卸货后清空木架；采矿时改背箩筐，装石回仓、略微前倾；食物仍用原货物标记。不自动派工，不改旧存档。

本机优先使用 `Assets/Gathering/Resources/Survivor/Survivor_LightOlive.fbx` 和同目录底色图。外观基于 Alves 的 [Realistic Male Character – Survivor](https://sketchfab.com/3d-models/realistic-male-character-survivor-e1a2b448d2a84b3db288eff3b619fcdb)，短衫、短裤和帆布鞋随同一骨架变形。缺少幸存者资源时回退到原农夫。

原农夫的 FBX 和 4 张贴图在本机 `Assets/Gathering/Resources/Farmer/`，不随 Git 分发。换机可从有授权的试装副本的 `Assets/FarmerTrial/` 恢复同名文件及对应 `.meta`，其中 `HairPacked.png` 是已合并透明通道的头发贴图。两套 FBX 都没有时 1 号也使用占位模型。走路／待机数据来自 Quaternius Universal Animation Library（CC0）；动作运行不需要试装工程或本机原生插件。

**调整建筑先后：** 左键点地图上的未完工工地，或打开「建造 → 建造顺序」从全场编号清单选中工地。可设「稍后／普通／优先」，也可「上移／下移／置顶」指定准确名次；跨档移动时沿用目标位置的档位。暂停时也能安排，顺序随存档保留。新工地在同档默认按放置先后。已完工和取消的工地不占名次。

空闲工人优先承接可达的靠前工地，已派人的靠前工地先领所缺材料。工人完成手头工作才切换；自动排入的后续工地会跟随新顺序，手动追加的任务保留原顺序。在途材料继续送往原工地，其他工地仍可使用多余人手和库存，因此排名不保证完工顺序。

## 2026-11-16 采集流程优化

## 代码边界

## 采集效率与数据库准备

右上角“采集效率”展开统计：本窗口入库件数、重量、趟数、平均件/分和 kg/分、最近 30 秒件/分、途中携货及每种资源的收益。时间占比分为行走、采集、等待工作位、等待卸货位、卸货、受阻、空闲；暂停不计时。所有工人都纳入累计工人秒，所选人员另有汇总。等候期间走向排队位置仍归入等待，不与行走重复计算。

“重新统计”只清观察窗口，库存和当前任务保留；窗口开始前已经携带的货物在卸货后会计入新窗口。“导出统计”在 `Application.persistentDataPath/GatheringReports/` 写 JSON，界面提示实际路径。这些报告不包含可恢复的完整世界状态，不能代替游戏存档。

`GatheringBenchmarks.Start()` 在 Play Mode 执行十组真实导航对照：木材不同单重、件数/载重限制、采集速度、步速、1/4/12 人，以及矿石/果实。每组重建场景，一人一趟；从派工到最后入库计时。单轮数据不是长期稳态产能。结果检查资源守恒、交付数量/重量/类型、采集工时、阶段工人秒、暂停与统计重置。结果在 `../output/unity-gathering/efficiency-benchmarks.json`、`.csv` 和 `efficiency-report.zh-CN.md`。

后端与数据库设计见 `../docs/backend-database.zh-CN.md`，初始 PostgreSQL 草案见 `../backend/database/001_initial.sql`。当前未接入/部署服务；稳定实体 ID 和版本化本地存档已完成，后续可接服务端权威模拟与原子检查点提交。采集实时状态不逐帧写库。
